# 第二阶段重构计划（稳定性优先，兼顾健壮性与性能）

## 1. Summary

- 本阶段目标：在不新增业务功能的前提下，优先修复潜在 Bug，其次提升代码健壮性，最后做可量化性能优化。
- 重点对象（按风险与收益排序）：
  1. `FilesFragment` 相关网络打开链路（Files/Favorites/NetworkConfig 协同）
  2. 远程传输与目录加载（FTP/SMB）异常处理与资源开销
  3. `ReaderFragment` 的 MHTML 降级检测可靠性
- 非目标：不做 UI 风格改造、不做数据库 schema 变更、不引入新协议类型。

## 2. Current State Analysis

### 2.1 高风险点（Bug 倾向）

1. 收藏网络路径打开存在“凭据依赖不一致”风险  
   - 文件：`app/src/main/java/html_reader/FavoritesFragment.kt`、`app/src/main/java/html_reader/files/FilesFavoritePathBuilder.kt`  
   - 现象：收藏路径已做脱敏（FTP 不保存密码），但 `FavoritesFragment` 仍依赖 `Uri.userInfo` 兜底创建临时配置。无匹配网络配置时，可能导致打开失败或体验不一致。

2. 远程 I/O 失败路径错误语义不稳定  
   - 文件：`app/src/main/java/html_reader/files/FilesTransferGateway.kt`  
   - 现象：使用 `error("open input stream failed")` 触发通用异常，调用层难区分“权限问题 / 文档不可读 / 临时 I/O 失败”，影响可观测性与恢复策略。

3. MHTML 布局降级仍依赖 `evaluateJavascript`  
   - 文件：`app/src/main/java/html_reader/ReaderFragment.kt`（`maybeRetryMhtmlWithFallback`）  
   - 现象：检测路径仍受 WebView JS 配置影响，存在“逻辑存在但触发不稳定”的历史问题残留。

### 2.2 健壮性问题

1. 跨页面网络打开逻辑重复、规则分散  
   - 文件：`FilesFragment.kt`、`FavoritesFragment.kt`、`files/FilesStartupHandler.kt`  
   - 影响：同一类路径（FTP/SMB）在不同页面被不同规则解析，维护成本高、回归风险高。

2. 状态与错误展示虽已拆分，但页面内状态机仍偏隐式  
   - 文件：`FilesFragment.kt`、`ReaderFragment.kt`  
   - 影响：异常分支靠 UI 文本推断，缺少统一错误码/分类，难做自动化校验。

### 2.3 性能问题

1. 远程目录加载与文件传输缺少统一限速/重试/超时策略  
   - 文件：`files/FilesTransferGateway.kt`、`files/FilesSmbGateway.kt`、`files/FilesNetworkGateway.kt`
2. `FilesFragment` 仍有较大体量（约 1200+ 行），高频逻辑混在 UI 编排中，后续优化粒度受限。

## 3. Proposed Changes

## 3.1 工作流 A：网络收藏打开链路收敛（Bug 优先）

### A1. 统一“网络收藏打开”规则

- 目标文件：
  - `app/src/main/java/html_reader/FavoritesFragment.kt`
  - `app/src/main/java/html_reader/files/FilesFavoritePathBuilder.kt`
  - `app/src/main/java/html_reader/files/FilesStartupHandler.kt`
- 方案：
  1. 新增 `files/FilesNetworkOpenResolver.kt`（新文件）
     - 输入：收藏路径、`networkConfigs`、`sourceType`
     - 输出：`ResolvedNetworkOpen`（包含 `configId`、`openPath`、`needCredential`）
  2. `FavoritesFragment.openNetworkFavorite` 改为只调用 resolver，不再直接拼接临时配置策略。
  3. 对无匹配配置且收藏无凭据场景，返回明确错误类型（如 `MISSING_CREDENTIAL`），统一展示文案与引导（跳转网络配置页）。
- 原因：先消除“同路径不同页面行为不一致”的潜在 Bug。

### A2. 明确脱敏收藏的契约

- 目标文件：
  - `app/src/main/java/html_reader/files/FilesFavoritePathBuilder.kt`
  - `app/src/main/res/values/strings.xml`
- 方案：
  1. 在收藏动作成功提示中增加说明：网络收藏不保存密码，打开依赖网络配置。
  2. 收藏落库契约维持不变（继续不存明文密码）。
- 原因：防止用户误判“收藏即含凭据”。

## 3.2 工作流 B：远程传输错误模型与健壮性提升

### B1. 传输层异常分类

- 目标文件：
  - `app/src/main/java/html_reader/files/FilesTransferGateway.kt`
  - `app/src/main/java/html_reader/files/FilesErrorFormatter.kt`
  - `app/src/main/java/html_reader/FilesFragment.kt`
- 方案：
  1. 新增 `files/FilesTransferException.kt`（新文件）定义 `InputUnavailable/AuthFailed/ConnectionFailed/PermissionDenied/Unknown`。
  2. 将 `error("open input stream failed")` 替换为 typed exception。
  3. `FilesErrorFormatter` 增加 transfer exception 分支，避免全部落入通用 message。
- 原因：减少“报错不清晰”与误导提示，提升恢复效率。

### B2. 资源开销控制（小步）

- 目标文件：
  - `app/src/main/java/html_reader/files/FilesTransferGateway.kt`
  - `app/src/main/java/html_reader/files/FilesSmbGateway.kt`
- 方案：
  1. 统一缓冲区常量并集中配置（避免魔法值散落）。
  2. 增加目录加载/传输耗时日志（仅 debug），便于后续性能基线比较。
- 原因：先建立可观测性，再做深度优化。

## 3.3 工作流 C：Reader MHTML 降级可靠性修复

### C1. 去 JS 依赖检测（优先）

- 目标文件：
  - `app/src/main/java/html_reader/ReaderFragment.kt`
  - `app/src/main/res/layout/fragment_reader.xml`
  - `core/reader/web/`（新增 `MeasuringWebView.kt`）
- 方案：
  1. 使用自定义 WebView 暴露内容宽度，替代 `evaluateJavascript` 获取文档宽度。
  2. 保留 `BlockingResourceWebViewClient` 的外链拦截策略不变。
  3. 仅在宽度检测结果明确时触发 `MHTML_FALLBACK`，避免重复 reload。
- 原因：修复已知不稳定点，避免再次出现“逻辑存在却不触发”。

## 3.4 工作流 D：FilesFragment 第二阶段结构收敛（本阶段末位）

- 目标文件：
  - `app/src/main/java/html_reader/FilesFragment.kt`
  - `app/src/main/java/html_reader/files/`（新增小型 helper）
- 方案：
  1. 将 `requestStoragePermission` 和远程动作弹窗组装进一步外移。
  2. 将 `runOperation` 的 UI 更新回调映射独立成 `FilesOperationUiBinder`（新文件）。
  3. 目标不是单纯压行数，而是将高风险逻辑从 Fragment 剥离，降低回归面。

## 4. Assumptions & Decisions

- 决策（已锁定）：
  - 首要目标：修复潜在 Bug
  - 次目标：提升健壮性
  - 再目标：性能优化
  - 允许跨页面联动重构
  - 验收采用“三者平衡”
- 假设：
  - 网络配置仍由 `MoreFragment` 维护，不在本阶段改造其交互模型。
  - 不新增数据库字段；凭据仍只存于网络配置，不存于收藏。
  - 不改变核心导航入口（`MainActivity` 路由保持原样）。

## 5. Verification Steps

### 5.1 构建与静态检查

1. `GetDiagnostics`：所有变更文件无新增错误。  
2. `.\gradlew.bat :app:assembleDebug`：构建通过。  

### 5.2 关键回归（功能）

1. 收藏打开 FTP/SMB：
   - 已有匹配网络配置：可直接打开。
   - 无匹配配置且收藏无凭据：给出明确提示并可引导到网络配置。
2. Files 网络上传下载：
   - 输入流不可用、连接失败、鉴权失败提示准确。
3. Reader MHTML：
   - 窄布局触发 fallback；宽布局不触发；无 JS 依赖回退失败。

### 5.3 关键回归（性能/资源）

1. 远程目录加载耗时日志可观测。  
2. 传输链路无明显额外内存峰值（与现状持平或下降）。  

## 6. 执行顺序

1. 工作流 A（收藏打开链路）  
2. 工作流 B（传输异常与健壮性）  
3. 工作流 C（Reader MHTML 检测可靠性）  
4. 工作流 D（FilesFragment 次级收敛）  
5. 全量回归与提交收敛
