## 1. 结论摘要

上一轮 `7db9a5d` 修复了 H1/M1/M2/M3/M4 的主体逻辑，方向正确，但引入了 **1 个 UI 回归**（网络配置对话框匿名选项消失），且历史遗留的 **Hilt 死代码（M5）** 与 **CacheEvictor 缺陷** 仍未解决。本轮新发现 3 个可稳定触发的崩溃/数据丢失路径。

**优先级最高的 7 条（P0）**：

1. `MoreFragment` 网络配置对话框的 `anonymousCheck` 从未 `addView`（回归，FTP 匿名模式 UI 消失）
2. 阅读页旋转/配置变更后空白（不恢复已打开内容）
3. 后台打开文件路径异常时未捕获异常直接 FATAL；`CancellationException` 被吞后写已销毁视图
4. `MoveUseCase` AUTO_RENAME 会覆盖并丢失目标目录中的同名文件
5. `CacheEvictor.makeRoomFor` 在文件超过缓存上限时会删光全部缓存（含本次刚建目录）
6. 收藏 `ftp://user:pass@host/...` 明文凭据入库，并随 JSON 备份导出（绕过 Keystore）
7. `CacheEvictor` 淘汰不排除活跃 tab 缓存，可能删除正在阅读的文件

## 2. 已验证问题清单

### 2.1 P0（崩溃 / 数据丢失 / 安全回归）

#### P0-1 网络配置对话框 FTP 匿名复选框消失（回归）
- 位置：`app/src/main/java/html_reader/MoreFragment.kt:189-197`（尤其 `:193`）
- 机制：`7db9a5d` 将 `root.addView(anonymousCheck)` 替换为 `decryptWarning?.let { root.addView(it) }`，全文件再无 `addView(anonymousCheck)`（grep 确认）。`anonymousCheck` 仍参与 `isChecked` 与监听逻辑，但用户不可见、不可操作。
- 影响：FTP 匿名模式无法切换；编辑匿名配置时无法取消匿名；`applyAuthUiState` 对不可见控件读写；`decryptFailed && password.isBlank()` 校验对匿名配置误报（`:270`）。
- 建议修复：
  1. 恢复 `root.addView(anonymousCheck)`，`decryptWarning` 单独插入；
  2. 保存校验改为 `if (decryptFailed && password.isBlank() && !useAnonymous)`；
  3. 顺带修复 `:189` 的缩进丢失。

#### P0-2 旋转后阅读页空白
- 位置：`app/src/main/java/html_reader/ReaderFragment.kt:134`、`:163-173`、`:189`
- 机制：`savedInstanceState` 恢复 `selectedTabId`；`currentTabId` 收集器仅在 `tabId != selectedTabId` 时调用 `loadSelectedTabContent()`（全文件仅 `:167`、`:170` 两处调用）；自动打开分支要求 `savedInstanceState == null`。`ReaderRuntime.viewModel` 为进程内单例，旋转后 `currentTabId == selectedTabId`，因此 Web/PDF 都不会加载；`fragment_reader.xml` 两个预览控件初始 `visibility=gone`。
- 影响：旋转/深色模式切换/分屏后阅读区空白，必须手动切 tab 才能恢复。
- 建议修复：在 `tabs` 首次发射后，若 `selectedTabId != null` 且尚未加载内容，无条件调用一次 `loadSelectedTabContent()`（幂等）。

#### P0-3 后台打开异常 → 未捕获协程异常崩溃；取消被吞 → 写已销毁视图
- 位置：`core/cache/CacheOpenManager.kt:96-99`、`core/reader/tab/DefaultReaderTabManager.kt:78-91`、`app/src/main/java/html_reader/FilesFragment.kt:696-710`、`app/src/main/java/html_reader/files/FilesOperationRunner.kt:42-43`
- 机制：
  - `CacheOpenManager` 在 `emit(Result.failure(e))` 之后仍 `throw AppError.IoError(...)`，`collect` 抛出异常使 `DefaultReaderTabManager` 的 `copyFailure?.let { emit(OpenState.Error) }` 不可达；
  - `FilesFragment.openFileInBackground` 的 `lifecycleScope.launch` 无 try/catch（前台 `ReaderFragment.runOpen:214-259` 有），远程后台打开（`FilesFragmentEntryDialogs.kt:222/224/226`）同样进入该路径；
  - `FilesOperationRunner` 捕获 `CancellationException` 后调用 `onError` 而非重抛，`FilesFragment.runOperation:522-529` 的 `finally` 继续 `loadEntries()`/`persistCurrentDir()`，视图销毁后可能 `Fragment not attached`。
- 影响：源文件 IO 错误或视图销毁时应用崩溃。
- 建议修复：`CacheOpenManager` 失败仅 `emit(Result.failure)`（取消仍重抛）；`openFileInBackground` 加 `try/catch` 并对 `CancellationException` 重抛；`FilesOperationRunner` 对取消重抛。

#### P0-4 Move AUTO_RENAME 覆盖已有文件（数据丢失）
- 位置：`core/fileops/usecase/MoveUseCase.kt:27-33`、`core/vfs/local/LocalFileSystem.kt:238-249`
- 机制：`NameConflictResolver.resolve` 探测到 `file.ext` 已存在后返回 `file(1).ext`；但 `fileSystem.move(from, toDir)` 固定移动到 `toDir/file.ext`（`src.renameTo(dst)`，POSIX 下覆盖同名文件），之后才 `rename` 为 `file(1).ext`。目标目录中原有的 `file.ext` 被静默销毁。
- 影响：自动重命名策略下丢数据；`rename` 失败时无回滚，留下中间态。
- 建议修复：`move` 支持目标全名（或在 UseCase 内先校验默认目标不存在，存在则中止/抛错）；失败回滚；补单测。

#### P0-5 CacheEvictor 可能删光缓存 / 删除活跃 tab 缓存
- 位置：`core/cache/CacheEvictor.kt:26-42`、调用点 `core/cache/CacheOpenManager.kt:49-70`
- 机制：`limit = maxBytes - requiredBytes` 可为负；循环按 mtime 删除直到 `total <= limit`，若 `requiredBytes > maxBytes` 会删除**所有** keyDir，包括 `CacheOpenManager:51-52` 刚创建、随后 `:79` 要写入的 `cacheDir`，导致 `FileNotFoundException`；`makeRoomFor` 也未排除 `TabCacheRegistry.activeCacheKeys()`（`OrphanCacheCleaner` 有该排除），活跃 tab 的缓存可能被删。
- 影响：超大文件永远打不开且顺带清空缓存；阅读中的 tab 切回时报缓存丢失。
- 建议修复：`requiredBytes >= maxBytes` 直接拒绝（返回错误）；注入/传入活跃 key 集合并跳过；调用方排除当前 `cacheKey`；补「超大文件」「活跃 tab」两个单测。

#### P0-6 收藏路径中的 FTP 明文凭据入库并随备份导出
- 位置：`app/src/main/java/html_reader/FavoritesFragment.kt:249-300`、`app/src/main/java/html_reader/files/FilesNetworkOpenResolver.kt:54-70`、`core/backup/JsonBackupManager.kt`（`FavoriteEntity.toDto` 的 `path = path`）
- 机制：收藏输入不做净化直接入库；`FilesNetworkOpenResolver` 会从收藏 URL 的 `userInfo` 解出用户名/密码（`:54-56`）构造 ad-hoc 配置。网络配置导出时密码置空（`JsonBackupManager.kt:220`），但收藏/历史的 `path` 原样导出。
- 影响：`ftp://user:pass@host/...` 明文存于 Room 与导出 JSON，违反 `CLAUDE.md 2.2.6`，绕过 `CredentialCipher`。
- 建议修复：收藏入库前剥离/拒绝 userInfo（提示用户改用网络配置）；导出时对 favorites/history 的 path 做 userInfo 清洗。

#### P0-7 同 2.1-P0-5 的活跃 tab 维度（合并说明）
- 见 P0-5 第 2 点。

### 2.2 P1（安全 / 稳定性 / 一致性）

#### P1-1 远程上传/下载不受操作锁保护，且取消被吞
- 位置：`app/src/main/java/html_reader/files/FilesRemoteController.kt:270-292`（下载）、`:294-313`（上传）
- 机制：仅本地 `runOperation` 与 SMB 变更操作使用 `tryAcquireOperationLock()`；上传/下载直接 `hostLifecycleScope.launch`，可与本地删除/重命名、SMB 操作并发写状态栏与进度条；`runCatching` 捕获 `CancellationException` 后仍 `updateStatus`（视图销毁后）。
- 建议修复：统一走操作锁；`runCatching` 改为显式 `catch (ce: CancellationException) { throw ce }`。

#### P1-2 远程下载临时文件唯一键缺配置身份 + 无原子写
- 位置：`app/src/main/java/html_reader/files/FilesTransferGateway.kt:29`、`:51`、`FilesNetworkGateway.createUniqueCacheFile:94-105`
- 机制：`uniquenessKey = "ftp:$remotePath"`（SMB 同理）不含 host/port/username，两台服务器同路径会落到同一文件；写入用 `FileOutputStream(target)` 直写，双击/并发时截断交错；无 `.part` 中间文件。
- 建议修复：key 加 `config.id`/host+user；写 `.part` 后原子改名；同一 key 做 in-flight 去重。

#### P1-3 同一 src 并发 openToCache 无 single-flight
- 位置：`core/reader/tab/DefaultReaderTabManager.kt:43-56`、`:132-159`、`core/cache/CacheOpenManager.kt:63-67`
- 机制：预检与最终写入不在同一临界区，两个并发请求（双击、前台+后台同时打开）都会通过预检并各自写同一 `cacheFile`；`cacheFile.length() == totalBytes` 的完成校验可能误判。
- 建议修复：以 `cacheKey` 为键的 Mutex/single-flight；写临时文件 + 原子替换。

#### P1-4 WebView 外链拦截可绕过
- 位置：`core/reader/web/BlockingResourceWebViewClient.kt:46-56`
- 机制：`shouldOverrideUrlLoading` 仅对「http(s) 且 hasGesture」返回 true；非手势 http(s)（meta refresh/服务端跳转）与非 http scheme（`intent:`、`file:` 等）均返回 false 交给 WebView 默认处理。`shouldInterceptRequest` 白名单为宽泛的 `file://`（任意本地文件可作子资源）。
- 建议修复：未识别 scheme 一律拦截；非手势 http(s) 也拦截；`file://` 白名单收窄到缓存目录前缀。

#### P1-5 decryptFailed 未在浏览链路处理
- 位置：`app/src/main/java/html_reader/FilesFragmentSession.kt:65-66`、`app/src/main/java/html_reader/files/FilesStartupHandler.kt:28-33`
- 机制：Keystore key 失效时 `NetworkConfigRepository.withDecryptedPassword` 返回 `enc:v1:` 密文并标记 `decryptFailed`，但会话/启动路径不检查，密文被当作密码拼进 FTP URL / SMB 认证。
- 建议修复：所有消费 `config.password` 的入口检查 `decryptFailed`，阻断连接并提示去 MoreFragment 重设密码。

#### P1-6 网络配置唯一索引冲突未捕获 → 崩溃
- 位置：`core/database/entity/NetworkConfigEntity.kt:11-16`（unique index）、`app/src/main/java/html_reader/MoreFragment.kt:285-295`、`app/src/main/java/html_reader/HomeFragment.kt:159-172`
- 机制：`@Insert` 默认 `ABORT`，仓库不捕获 `SQLiteConstraintException`，两个入口都在 `lifecycleScope.launch` 中无 try/catch。
- 建议修复：捕获约束异常提示「配置已存在」，或 `OnConflictStrategy.IGNORE` 并返回既有 id；编辑场景先做业务查重。

#### P1-7 CacheEvictor / OrphanCacheCleaner 漏统计 L0/L1 散落文件（历史 L1 仍在）
- 位置：`core/cache/CacheEvictor.kt:14-42`、`core/cache/OrphanCacheCleaner.kt:17-27`
- 机制：仅遍历 `cacheRoot/<typeDir>/<keyDir>` 两层；直接位于 `cacheRoot` 或 `cacheRoot/<typeDir>` 的文件不计入总大小、不参与淘汰/清理。
- 建议修复：统一递归 `walkTopDown` 聚合并清理根级散落文件。

#### P1-8 备份导入非事务且先清库；`withEncryptedPassword` 不判 `isEncrypted`
- 位置：`core/backup/JsonBackupManager.kt:93-104`（`clearEverything` 后逐条写）、`core/data/repo/NetworkConfigRepository.kt:81-82`
- 机制：导入中途失败会留下半清空数据；`encrypt()` 只判空不判前缀，手工/第三方备份中的 `enc:v1:` 值会被二次加密导致永久不可解。
- 建议修复：导入包在 Room 事务内、先校验后提交；`withEncryptedPassword` 对 `isEncrypted` 原样返回。

#### P1-9 历史进度读改写竞态
- 位置：`core/data/repo/HistoryRepository.kt:14-27`
- 机制：`getByPath` → 组装 → `upsert(REPLACE)` 非原子；`recordOpen` 在 `Ready` 之后执行，可能覆盖已写入的 `updateProgress`，进度偶发归零。
- 建议修复：单条 `INSERT ... ON CONFLICT(path) DO UPDATE SET title/lastAccess/fileType`，保留 progress/pageIndex。

#### P1-10 FolderSession 全量更新回退 sortOption
- 位置：`core/session/repo/FolderSessionRepository.kt:29-41`、`core/session/dao/FolderSessionDao.kt:27-28`
- 机制：`updateCurrentDir/switchTo` 先读整行再 `@Update` 覆盖；与 `updateSortOption` 并发时旧 `sortOption` 覆盖新值。
- 建议修复：改用列级 `@Query` 更新。

#### P1-11 MainActivity 返回键与高亮
- 位置：`app/src/main/java/html_reader/MainActivity.kt:48-69`、`:261-276`
- 机制：`favorites_page`/`recents_page` 无返回分支，落到 `isEnabled=false; onBackPressedDispatcher.onBackPressed()` → 直接退出；`syncBottomNavSelection` 的 `else` 把它们高亮为 Home；`isUserNavigation`（`:24`）赋值后从未读取；`switchFragment` 用异步 `commit()`，`getCurrentVisibleFragment()` 在 commit 前仍是旧页（快速连点/立即返回竞态）。
- 建议修复：为两个 tag 增加返回分支（回 Home）；改用 `commitNow()` 或 `runOnCommit` 后同步高亮；删除或使用 `isUserNavigation`。

#### P1-12 标题缓存无运行时清理
- 位置：`core/work/TitleCacheCleanupWorker.kt`、`core/maintenance/DefaultMaintenanceManager.kt`（均未接线）
- 机制：生效路径只有 `AppHistoryRetentionWorker` + `AppOrphanCacheCleanupWorker` + 启动清理，`title_cache` 表随浏览无限增长。
- 建议修复：把标题缓存清理并入生效 Worker（参数走 `AppMaintenancePolicy`）。

#### P1-13 网络错误透传原始异常（可能含凭据 URL）
- 位置：`app/src/main/java/html_reader/files/FilesErrorFormatter.kt:39`、`FilesNetworkGateway.kt:50-67`
- 机制：兜底 `return msg.ifBlank { ... }` 把底层异常消息原样展示并绑定「复制」；FTP URL 含明文用户名/密码，异常消息一旦携带 URL 即暴露。
- 建议修复：错误映射改为「分类 + 资源字符串」，兜底文案脱敏（正则擦除 `://user:pass@`）。
